1.1 Oracle Instance

وهي تتكون من جزئين رئيسيين كما في الشكل أعلاه:

  • Memory Structure - هيكل الذاكرة
  • Background Processes - العمليات الخلفية

1.1.1 Memory Structure

وهي تتكون لحظة فتح الـ Instance وهي عبارة عن جزء من الذاكرة يتم تخصيصه لعمل قاعدة البيانات Oracle وهي تتكون من جزئين:

  • 1- System Global Area (SGA)
  • 2- Program Global Area (PGA)
1.1.1.1 System Global Area (SGA)

وتسمى أيضاً Shared Global Area وهي جزء من الذاكرة يخصص للمعلومات التي تكون مشتركة ومتاحة لجميع مستخدمي قواعد البيانات، وتحتوي على معلومات التحكم التي تستخدم من قبل الـ Oracle Server وهي تتكون في الـ Virtual Memory وتتكون لحظة فتح الـ Instance، ومقاس هذه الذاكرة يتحدد بواسطة المتغير SGA_MAX_SIZE في ملف المتغيرات (Parameter File)، وهي ذاكرة Dynamic أي يمكن تغيير مقاسها دون إغلاق قاعدة البيانات وهي تتكون من قسمين:

1- Mandatory Memory
  • 1- Shared Pool: ويتم التحكم في مقاس هذه الذاكرة بواسطة المتغير SHARED_POOL_SIZE، وتحتوي على جزئين:
    • 1- Library Cache
    • 2- Data Dictionary Cache
  • 2- Database Buffer Cache: ويتم التحكم في مقاس هذا الجزء من الذاكرة بواسطة المتغير DB_CACHE_SIZE
  • 3- Redo Log Buffer: ويتم تحديد مقاس هذا الجزء من الذاكرة بواسطة المتغير LOG_BUFFER

وهكذا باقي أجزاء الذاكرة يتم التعديل بنفس الطريقة السابقة.

2- Optional Memory
  • 1- Large Pool
  • 2- Java Pool
  • 3- Streams Pool
1.1.1.2 Program Global Area (PGA)

وتسمى أيضاً Process Global Area وهو جزء من الذاكرة يتكون خارج الـ Instance وهو يحتوي على معلومات خاصة للـ Server Process الحالي ويتكون هذا الجزء من الذاكرة لحظة إنشاء الـ Server Process وتنتهي لحظة انتهاء الـ Server Process. وهذا الجزء ليس متاحاً لباقي المتصلين أي لكل Server Process في قاعدة البيانات PGA خاصة به تحتوي على معلومات خاصة به. وهي تحتوي على ثلاثة أجزاء:

  • 1- Private SQL Area
  • 2- Session Memory
  • 3- SQL Work Area

أنواع العمليات (Processes)

وقبل الحديث عن الـ Background Processes لا بد من الذكر بأن هناك ثلاثة أنواع من الـ Processes:

1- User Process

وهو يبدأ العمل عندما يطلب المستخدم الاتصال بقواعد البيانات عن طريق أحد أدوات قواعد البيانات.

2- Server Process

ويتم إنشاؤه لحظة الاتصال بالـ Instances بعد طلب الـ User Process الاتصال بقواعد البيانات فيتم التحقق من المستخدم فلحظة الاتصال هي لحظة إنشاء الـ Server Process، وهو يكون بين الـ User Process والـ Instance، فلكل User Process في قاعدة البيانات Server Process خاص به هذا إذا كنا نعمل في بيئة الـ Dedicated Server أما إذا كنا نعمل في بيئة الـ Shared Server فالأمر يختلف قليلاً، عموماً سنناقش هذا الأمر لاحقاً.

3- Background Processes

وهو موضوع نقاشنا في هذه الفقرة وهي عبارة عن معالجات تعمل في قاعدة البيانات بحيث تقوم بمهام مختلفة تبدأ العمل لحظة فتح الـ Instance، وتنقسم إلى قسمين:

  • 1- Mandatory: لا بد من عملها لحظة فتح الـ Instance
  • 2- Optional: وبدونها تستطيع الـ Instance العمل وهذا النوع يعمل في بعض الأحوال التي يتم فيه تهيئة قاعدة البيانات للعمل على خيارات معينة

إدارة التخزين - Tablespace Management

إدارة الـ Tablespace

يتم إدارة الـ (extent) عن طريق الـ (bitmap) وهو الطبيعي عند الإنشاء: locally

إدارة الـ extent
Automatic

التقسيم يتم عن طريق النظام ولا يمكن استخدام هذا النوع في الـ temp

Uniform

يتم تحديد حجم الـ extent عن طريقنا الأصل هو 1MB لا يمكن استخدام هذا النوع مع undo

Data Dictionary

يتم التقسيم عن طريق قاموس البيانات

ملاحظة: أوراكل لديها بعض الحدود لتعيين الحد الأقصى لحجم ملف البيانات بناء على متغير db_block_size

Logging

Yes

عند عمل أي تغيير في الكائنات يتم كتابة التغيرات في redo log file

No

لا يتم حفظها في redo log file

Mode

Read-only

لا نستطيع عمل كتابة أو تعديل أو حذف البيانات الموجودة في المساحة

Read Write

نستطيع عمل قراءة وكتابة وحذف وتعديل

تحذير: لا يمكننا وضع system أو sysaux في وضع القراءة فقط

Status

Online – Offline

الشرح: يعرض جميع مواقع الأرشيف المكونة في قاعدة البيانات. Oracle يدعم من 1-31 موقع أرشيف حسب الإصدار

تحديد موقع الأرشيف

الشرح: يحدد المجلد الذي سيتم حفظ ملفات الأرشيف فيه. يجب أن يكون المجلد موجوداً ولديه صلاحيات الكتابة

تكوين مواقع أرشيف متعددة

تكوين الموقع الأول للأرشيف (إجباري)

تكوين الموقع الثاني للأرشيف (اختياري للنسخ الاحتياطي)

ALTER SYSTEM SET log_archive_dest_2='LOCATION=F:\backup\archive2';

الشرح: يمكن تكوين مواقع متعددة للأرشيف لضمان الحماية. الموقع الأول إجباري، والمواقع الأخرى اختيارية

إلغاء تفعيل موقع الأرشيف

ALTER SYSTEM SET log_archive_dest_state_2=DISABLE;

مراقبة ملفات الأرشيف

إعدادات متقدمة للأرشيف

تحديد تنسيق اسم ملف الأرشيف

ALTER SYSTEM SET log_archive_format='arch_%t_%s_%r.arc';

تحديد الحد الأقصى لعمليات الأرشيف المتزامنة

ALTER SYSTEM SET log_archive_max_processes=4;

الشرح:

  • %t = رقم الخيط (Thread)
  • %s = رقم التسلسل (Sequence)
  • %r = رقم إعادة التشغيل (Resetlogs ID)
  • log_archive_max_processes = عدد العمليات المتزامنة للأرشفة

    FAILED_LOGIN_ATTEMPTS 3
    SESSIONS_PER_USER 2
    PASSWORD_LOCK_TIME 7
    INACTIVE_ACCOUNT_TIME 30;

الشرح: ينشئ ملف شخصي يحدد جلسة لمدة ساعتين، صلاحية كلمة سر 90 يوم، 3 محاولات فاشلة، جلستين متزامنتين، قفل لمدة أسبوع، وقفل بعد 30 يوم من عدم النشاط

تعديل ملف شخصي (Alter Profile)

تعديل وقت الاتصال في الملف الشخصي

ALTER PROFILE pro_hr LIMIT CONNECT_TIME 160;

تعديل عدة معاملات في نفس الوقت

ALTER PROFILE pro_hr LIMIT
    PASSWORD_LIFE_TIME 120
    FAILED_LOGIN_ATTEMPTS 5;

الشرح: يعدل معاملات الملف الشخصي الموجود دون الحاجة لإعادة إنشائه

عرض الملفات الشخصية

عرض جميع الملفات الشخصية

SELECT * FROM DBA_PROFILES;

عرض ملف شخصي محدد

SELECT * FROM DBA_PROFILES WHERE PROFILE = 'PRO_HR';

الشرح: يعرض تفاصيل جميع الملفات الشخصية أو ملف محدد مع قيم المعاملات

حذف ملف شخصي (Drop Profile)

حذف الملف الشخصي مع CASCADE

DROP PROFILE pro_hr CASCADE;

الشرح: يحذف الملف الشخصي ويحول جميع المستخدمين المرتبطين به إلى الملف الافتراضي DEFAULT

تحذير: استخدم CASCADE لحذف الملف حتى لو كان مرتبط بمستخدمين

إدارة المستخدمين - User Management

إعدادات النظام المطلوبة

تفعيل إنشاء المستخدمين العاديين (غير Common Users)

ALTER SESSION SET "_oracle_script"=TRUE;

إزالة بادئة المستخدمين المشتركين

ALTER SYSTEM SET common_user_prefix='' SCOPE=SPFILE;

الشرح: هذه الإعدادات ضرورية في Oracle 12c وما بعد لإنشاء مستخدمين عاديين بدون بادئة C##

إنشاء مستخدم جديد (Create User)

إنشاء مستخدم شامل مع جميع الإعدادات

CREATE USER user_name
IDENTIFIED BY password123
DEFAULT TABLESPACE USERS
TEMPORARY TABLESPACE TEMP
PROFILE pro_hr
QUOTA 100M ON USERS;

مثال عملي لإنشاء مستخدم HR

CREATE USER hr_user
IDENTIFIED BY hr123456
DEFAULT TABLESPACE USERS
TEMPORARY TABLESPACE TEMP
PROFILE pro_hr
QUOTA UNLIMITED ON USERS;

الشرح المفصل:

  • IDENTIFIED BY: كلمة السر للمستخدم
  • DEFAULT TABLESPACE: مساحة التخزين الافتراضية
  • TEMPORARY TABLESPACE: مساحة التخزين المؤقتة
  • PROFILE: الملف الشخصي المطبق
  • QUOTA: حد المساحة المسموحة
عرض معلومات المستخدمين

عرض جميع المستخدمين

SELECT * FROM DBA_USERS;

عرض معلومات مستخدم محدد

SELECT username, account_status, profile, default_tablespace, created
FROM DBA_USERS
WHERE username = 'HR_USER';

الشرح: يعرض معلومات شاملة عن المستخدمين مثل حالة الحساب، الملف الشخصي، ومساحة التخزين

تعديل المستخدمين (Alter User)
فتح الحساب المقفل

فتح الحساب وتغيير كلمة السر

ALTER USER hr_user IDENTIFIED BY newpassword123 ACCOUNT UNLOCK;
تغيير كلمة السر

تغيير كلمة السر فقط

ALTER USER hr_user IDENTIFIED BY newpassword456;
انتهاء صلاحية كلمة السر

إجبار المستخدم على تغيير كلمة السر في الدخول التالي 

ALTER USER hr_user PASSWORD EXPIRE;
قفل الحساب

قفل الحساب مؤقتاً

ALTER USER hr_user ACCOUNT LOCK;
تغيير مساحة التخزين

تغيير مساحة التخزين الافتراضية

إدارة الصلاحيات - Privileges Management

أنواع الصلاحيات في Oracle
System Privileges

صلاحيات على مستوى النظام مثل إنشاء الجداول والاتصال

Object Privileges

منح الصلاحيات الأساسية (Grant System Privileges)
صلاحية الاتصال

منح صلاحية الاتصال بقاعدة البيانات

GRANT CONNECT TO hr_user;

الوصف: تسمح للمستخدم بالاتصال بقاعدة البيانات

صلاحية إنشاء الجداول

منح صلاحية إنشاء الجداول

GRANT CREATE TABLE TO hr_user;

الوصف: تسمح للمستخدم بإنشاء جداول في مساحة التخزين الخاصة به

صلاحية مع خيار Admin

منح صلاحية مع إمكانية منحها للآخرين

GRANT CREATE TABLE TO hr_user WITH ADMIN OPTION;

منح صلاحيات متقدمة

منح عدة صلاحيات في أمر واحد

GRANT SELECT ANY TABLE, UPDATE ANY TABLE TO hr_user;

منح صلاحية حذف أي جدول

GRANT DELETE ANY TABLE TO hr_user;

منح صلاحية إسقاط أي جدول

GRANT DROP ANY TABLE TO hr_user;

الشرح: صلاحيات ANY تعطي المستخدم صلاحيات على جميع الكائنات في قاعدة البيانات

تحذير: صلاحيات ANY قوية جداً ويجب منحها بحذر!

منح صلاحيات الكائنات (Object Privileges)

منح صلاحية قراءة جدول محدد

GRANT SELECT ON hr.employees TO hr_user;

منح عدة صلاحيات على جدول محدد

GRANT SELECT, INSERT, UPDATE, DELETE
ON hr.employees
TO hr_user;

الشرح: يمنح صلاحيات محددة على كائن معين (جدول، view، إلخ)

سحب الصلاحيات (Revoke Privileges)

سحب صلاحية الاتصال

REVOKE SELECT ON hr.employees FROM hr_user;

إدارة ملفات المعاملات - Parameter Files Management

ملفات المعاملات في Oracle: هناك نوعان من ملفات المعاملات - PFILE (Parameter File) و SPFILE (Server Parameter File). SPFILE هو الأحدث ويوفر إدارة أفضل للمعاملات

أنواع ملفات المعاملات
PFILE (Parameter File)
  • ملف نصي يمكن تحريره يدوياً
  • يتطلب إعادة تشغيل لتطبيق التغييرات
  • اسم الملف: INIT<SID>.ORA
  • يستخدم عند وجود مشاكل في SPFILE
SPFILE (Server Parameter File)
  • ملف ثنائي لا يمكن تحريره يدوياً
  • يدعم التغيير الديناميكي للمعاملات
  • اسم الملف: SPFILE<SID>.ORA
  • الطريقة المفضلة في الإصدارات الحديثة
فحص ملفات المعاملات الحالية
فحص SPFILE
-- عرض مسار ملف SPFILE
SHOW PARAMETER SPFILE;

النتيجة المتوقعة: إذا كان فارغاً، فالنظام يستخدم PFILE

فحص PFILE
-- عرض مسار ملف PFILE (إذا كان مستخدماً)
SHOW PARAMETER PFILE;

النتيجة المتوقعة: يظهر المسار إذا كان النظام يستخدم PFILE

إنشاء PFILE من SPFILE
متى نحتاج إنشاء PFILE؟
  • عندما لا نجد ملف PFILE موجود
  • لإنشاء نسخة احتياطية قابلة للقراءة
  • لتحرير المعاملات يدوياً قبل إنشاء SPFILE جديد

إنشاء PFILE من SPFILE (بالاسم الافتراضي)

CREATE PFILE FROM SPFILE;

إنشاء PFILE بمسار ومسار محدد

CREATE PFILE='E:\backup\init_backup.ora' FROM SPFILE;

الشرح:

  • الأمر الأول: ينشئ ملف بالاسم الافتراضي INIT<SID>.ORA
  • الأمر الثاني: ينشئ ملف بالمسار والاسم المحدد
  • الملف المُنشأ: يحتوي على جميع المعاملات الحالية بصيغة نصية
حل مشاكل SPFILE
عند وجود مشكلة في SPFILE

إذا كان SPFILE تالفاً أو يحتوي على معاملات خاطئة تمنع بدء تشغيل قاعدة البيانات

الخطوة 1: بدء التشغيل باستخدام PFILE
-- بدء التشغيل باستخدام PFILE محدد
STARTUP PFILE='E:\oracle\init.ora';

الغرض: تجاوز SPFILE التالف واستخدام PFILE بدلاً منه

الخطوة 2: إنشاء SPFILE جديد من PFILE
-- إنشاء SPFILE جديد من PFILE الحالي
CREATE SPFILE FROM PFILE;

الغرض: إنشاء SPFILE جديد وسليم من PFILE المُصحح

الخطوة 3: إعادة التشغيل العادي
-- إعادة تشغيل قاعدة البيانات بالطريقة العادية
SHUTDOWN IMMEDIATE;
STARTUP;

الغرض: التأكد من أن النظام يستخدم SPFILE الجديد

إنشاء نسخة احتياطية من SPFILE

مهم جداً: قبل تعديل أي معاملات في SPFILE، يجب إنشاء نسخة احتياطية!

إنشاء نسخة احتياطية من SPFILE

CREATE PFILE='E:\backup\spfile_backup.ora' FROM SPFILE;

مثال بتاريخ ووقت

CREATE PFILE='E:\backup\spfile_backup_20241219.ora' FROM SPFILE;

فوائد النسخة الاحتياطية:

  • إمكانية الرجوع للإعدادات السابقة
  • مراجعة المعاملات قبل وبعد التغيير
  • حل سريع في حالة حدوث مشاكل
الاستعلام عن المعاملات

عرض جميع المعاملات مع الوصف

SELECT name, description FROM v$parameter;

البحث عن معامل محدد

SELECT name, value, description
FROM v$parameter
WHERE name LIKE '%sga%';

عرض المعاملات المُعدلة فقط

SELECT name, value, isdefault
FROM v$parameter
WHERE isdefault = 'FALSE';

الشرح:

  • v$parameter: يعرض جميع معاملات النظام الحالية
  • name: اسم المعامل
  • value: القيمة الحالية
  • description: وصف المعامل
  • isdefault: هل القيمة افتراضية أم مُعدلة
تعديل المعاملات (ALTER SYSTEM)
صيغة الأمر الأساسية

الصيغة العامة لتعديل المعاملات

ALTER SYSTEM SET parameter_name = value SCOPE = scope_option;
خيارات SCOPE
MEMORY

التأثير: على الجلسة الحالية فقط

المدة: ينتهي بإعادة التشغيل

الاستخدام: للاختبار المؤقت

مثال: تعديل مؤقت

ALTER SYSTEM SET sga_max_size = 2G SCOPE = MEMORY;
SPFILE

التأثير: على SPFILE فقط

المدة: يحتاج إعادة تشغيل

الاستخدام: للتطبيق في المرة القادمة

مثال: حفظ في SPFILE

ALTER SYSTEM SET shared_pool_size = 256M SCOPE = SPFILE;
BOTH

التأثير: فوري + حفظ في SPFILE

المدة: فوري ودائم

الاستخدام: الأفضل للتطبيق الفوري

مثال: تطبيق فوري ودائم

ALTER SYSTEM SET db_cache_size = 512M SCOPE = BOTH;
