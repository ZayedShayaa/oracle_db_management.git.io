الملفات الفيزيائية لقاعدة البيانات

1.1 Oracle Instance

وهي تتكون من جزئين رئيسيين كما في الشكل أعلاه:

  • Memory Structure - هيكل الذاكرة
  • Background Processes - العمليات الخلفية

1.1.1 Memory Structure

وهي تتكون لحظة فتح الـ Instance وهي عبارة عن جزء من الذاكرة يتم تخصيصه لعمل قاعدة البيانات Oracle وهي تتكون من جزئين:

  • 1- System Global Area (SGA)
  • 2- Program Global Area (PGA)
1.1.1.1 System Global Area (SGA)

وتسمى أيضاً Shared Global Area وهي جزء من الذاكرة يخصص للمعلومات التي تكون مشتركة ومتاحة لجميع مستخدمي قواعد البيانات، وتحتوي على معلومات التحكم التي تستخدم من قبل الـ Oracle Server وهي تتكون في الـ Virtual Memory وتتكون لحظة فتح الـ Instance، ومقاس هذه الذاكرة يتحدد بواسطة المتغير SGA_MAX_SIZE في ملف المتغيرات (Parameter File)، وهي ذاكرة Dynamic أي يمكن تغيير مقاسها دون إغلاق قاعدة البيانات وهي تتكون من قسمين:

1- Mandatory Memory
  • 1- Shared Pool: ويتم التحكم في مقاس هذه الذاكرة بواسطة المتغير SHARED_POOL_SIZE، وتحتوي على جزئين:
    • 1- Library Cache
    • 2- Data Dictionary Cache
  • 2- Database Buffer Cache: ويتم التحكم في مقاس هذا الجزء من الذاكرة بواسطة المتغير DB_CACHE_SIZE
  • 3- Redo Log Buffer: ويتم تحديد مقاس هذا الجزء من الذاكرة بواسطة المتغير LOG_BUFFER

وهكذا باقي أجزاء الذاكرة يتم التعديل بنفس الطريقة السابقة.

2- Optional Memory
  • 1- Large Pool
  • 2- Java Pool
  • 3- Streams Pool
1.1.1.2 Program Global Area (PGA)

وتسمى أيضاً Process Global Area وهو جزء من الذاكرة يتكون خارج الـ Instance وهو يحتوي على معلومات خاصة للـ Server Process الحالي ويتكون هذا الجزء من الذاكرة لحظة إنشاء الـ Server Process وتنتهي لحظة انتهاء الـ Server Process. وهذا الجزء ليس متاحاً لباقي المتصلين أي لكل Server Process في قاعدة البيانات PGA خاصة به تحتوي على معلومات خاصة به. وهي تحتوي على ثلاثة أجزاء:

  • 1- Private SQL Area
  • 2- Session Memory
  • 3- SQL Work Area

أنواع العمليات (Processes)

وقبل الحديث عن الـ Background Processes لا بد من الذكر بأن هناك ثلاثة أنواع من الـ Processes:

1- User Process

وهو يبدأ العمل عندما يطلب المستخدم الاتصال بقواعد البيانات عن طريق أحد أدوات قواعد البيانات.

2- Server Process

ويتم إنشاؤه لحظة الاتصال بالـ Instances بعد طلب الـ User Process الاتصال بقواعد البيانات فيتم التحقق من المستخدم فلحظة الاتصال هي لحظة إنشاء الـ Server Process، وهو يكون بين الـ User Process والـ Instance، فلكل User Process في قاعدة البيانات Server Process خاص به هذا إذا كنا نعمل في بيئة الـ Dedicated Server أما إذا كنا نعمل في بيئة الـ Shared Server فالأمر يختلف قليلاً، عموماً سنناقش هذا الأمر لاحقاً.

3- Background Processes

وهو موضوع نقاشنا في هذه الفقرة وهي عبارة عن معالجات تعمل في قاعدة البيانات بحيث تقوم بمهام مختلفة تبدأ العمل لحظة فتح الـ Instance، وتنقسم إلى قسمين:

  • 1- Mandatory: لا بد من عملها لحظة فتح الـ Instance
  • 2- Optional: وبدونها تستطيع الـ Instance العمل وهذا النوع يعمل في بعض الأحوال التي يتم فيه تهيئة قاعدة البيانات للعمل على خيارات معينة
